## 2. 실행 방법 (재현 가이드)

> 제3자가 그대로 따라 하면 같은 결과가 나오도록 작성합니다. _(단계 2~3 완료 후 채움)_

1. **실행 환경**: Python 3.10 이상, VS Code(노트북 실행용 Jupyter 확장 설치)
2. **라이브러리 설치** — `Project_01` 폴더에서 터미널을 열고:
   ```powershell
   python -m venv .venv              # 이 프로젝트 전용 파이썬 공간(가상환경) 만들기
   .venv\Scripts\activate            # 가상환경 켜기 (앞에 (.venv) 가 붙으면 성공)
   pip install -r requirements.txt   # 목록에 적힌 라이브러리를 정해진 버전으로 설치
   ```
3. **API 키 준비**: `.env.example`을 복사해 `.env`로 이름을 바꾸고, NAVER API HUB에서 받은 키를 입력
4. **데이터 수집** (API 호출은 이 한 번뿐):
   ```powershell
   cd Project_01                # 저장소 최상위에서 열었다면 먼저 이동
   .venv\Scripts\activate       # 가상환경 켜기
   python collect.py
   ```
   - 실행 전 확인: 줄 앞에 `(.venv)`, 경로 끝이 `\Project_01>` 인지. 터미널을 새로 열면 둘 다 초기화된다.
   → `data/search_trend_raw.json`(원본 응답), `data/search_trend_weekly.csv`(분석용 표) 생성
5. **분석 실행**: Cursor에서 `analysis.ipynb`를 열고
   - 오른쪽 위 **커널 선택(Select Kernel)** → `Python Environments` → 경로가 `.venv\Scripts\python.exe`인 항목을 고른다(라이브러리가 설치된 곳). 버전 숫자만 보고 고르면 컴퓨터 기본 파이썬과 헷갈린다.
   - 상단 **Run All**(모두 실행)으로 위에서부터 순서대로 실행

  ```python
  q1 = df.quantile(0.25); q3 = df.quantile(0.75)
  upper = q3 + 1.5 * iqr
  is_outlier = (df > upper) | (df < lower)
  ```
  - `quantile(0.25)`는 값을 줄 세웠을 때 25% 지점이다. 지역마다 따로 계산되므로 기준선도 지역마다 다르다(통영 41.2, 남해 58.3).

  ④ 후보가 언제 몰려 있는지 세기
  ```python
  outliers = df[is_outlier].stack()
  pd.crosstab(outliers["region"], outliers["month"])
  ```
  - `df[is_outlier]`는 True인 칸만 값을 남기고 나머지는 비운다. `stack()`은 비지 않은 칸만 골라 (날짜, 지역, 값) 목록으로 세운다.
  - `crosstab`은 두 기준(지역×월)으로 개수를 세는 집계표다. 엑셀 피벗테이블의 "개수" 기능과 같다.

  ⑤ 값은 두고 표시만 붙이기

  ```

  변화율 = df.pct_change() * 100
  ```
  - `pct_change()`는 (이번 주 − 지난주) ÷ 지난주를 계산한다. 0.25가 25%이므로 100을 곱해 % 단위로 바꿨다.
  - 첫 주는 비교할 지난주가 없어 빈칸이 된다. 이는 결측치가 아니라 계산상 당연한 빈칸이다.

  ④ 막대 색으로 방향 표시
  ```python
  색 = ["#3B5BDB" if v >= 0 else "#ADB5BD" for v in 변화율["통영"]]
  ```
  - 상승은 파랑, 하락은 회색으로 칠해 방향이 한눈에 보이게 했다. 색은 강조 수단이고, 값 자체는 축과 막대 길이로 읽는다.

  ⑤ 겹치는 날짜 라벨 (그림 4)
  ```python
  xytext=(0, 6 + 14 * (순위 % 2))
  ```
  - 상위 3개 중 2023-07-24와 2023-09-25는 두 달 차이라 글자가 겹쳤다. 순위가 홀수인 항목만 14픽셀 더 올려 번갈아 배치했다.

### 단계 7. 인사이트 도출 — 2026-09-19 ✅

작성 규칙(과제 Ⅳ-2): **관찰(그래프에서 확인한 수치)**과 **해석(가설)**을 반드시 나눠 쓴다.
해석·행동 문장은 제시된 선택지 중 본인이 고른 것이며, 인터뷰에서는 본인 표현으로 다시 말한다.

#### 인사이트 1 — 7월 정점, 11~12월 저점의 계절 구조

- **관찰(Fact)**: 5년 평균 월별 관심도에서 세 지역 모두 7월 최고·11~12월 최저. 통영 37.6 → 19.3(1.9배), 거제 17.7 → 7.8(2.3배), 남해 50.4 → 21.3(2.4배). 3월에 한 번 꺾였다가 4월부터 재상승. (그림 3)
- **해석(가설)**: 검색 관심이 휴가철에 몰리고 11~12월에 바닥을 치는 구조가 5년간 한 번도 깨지지 않았다.
- **행동(Action)**: 비수기 판촉은 12월이 아니라 관심이 바닥으로 내려가기 전인 11월 이전에 건다.

#### 인사이트 2 — 2025년 들어 세 지역 모두 관심도 하락

- **관찰(Fact)**: 연평균 통영 26.4(2024) → 20.2(2025), 거제 10.1 → 7.8, 남해 27.5 → 24.1. 거제는 2021년 13.2에서 5년 내리 하락. 2024년 후반부터 통영과 남해의 12주 이동평균 선이 거의 붙는다. (그림 2, 연도별 평균표)
- **해석(가설)**: 세 지역이 함께 빠진 것은 개별 지역의 문제가 아니라 남해안 권역 전체의 관심 이동으로 보인다.
- **검증이 필요한 부분**: 데이터랩 값은 전체 검색량의 비중이 아니라 **조회 기간 내 상대 지수**다. 세 지역이 함께 내려간 것이 "남해안 여행 관심 자체의 감소"인지 "다른 여행지로의 이동"인지는 이 데이터만으로 구분되지 않는다. 비교군(예: 해외 도시, 강원 지역) 검색어를 같은 요청에 넣어 다시 수집하면 확인할 수 있다.
- **행동(Action)**: 강원·해외 여행지를 비교군에 넣어 다시 수집해, 관심 감소인지 이동인지부터 가린다.

#### 인사이트 3 — 여름 쏠림이 5년간 완화

- **관찰(Fact)**: 비수기 비율(겨울 평균÷여름 평균)이 통영 0.55(2021) → 0.70(2025), 거제 0.49 → 0.79, 남해 0.55 → 0.62로 상승. 절대값을 보면 비율 상승은 겨울 증가보다 **여름 감소** 쪽이 크다(통영 여름 32.5 → 28.4, 겨울 17.9 → 20.0).
- **해석(가설)**: 성수기 수요가 줄어드는 만큼, 비수기 매출 비중을 올리는 전략의 실익이 커지고 있다.
- **행동(Action)**: 겨울 상품(요트·미식·워케이션) 검색어를 따로 수집해 비수기 수요의 실체를 확인한다.

- **AI 사용 내역**
  - 작업: 관찰 수치 정리, 해석·행동 문장 초안 제시(선택지 형태)
  - 이유: 해석의 재료를 모으고 표현을 다듬기 위함
  - 검증: 인사이트 3은 초안을 검토하다 "비율 상승 = 겨울 증가"로 읽힐 수 있음을 발견해, 여름·겨울 절대값을 다시 계산해 원인을 여름 감소로 바로잡음

- **인사이트 4(급등 주 원인) 삭제**: 급등 주와 연휴·장마 종료 시기가 겹친다는 것까지는 확인했으나, 인과를 검증하지 않은 가설을 인사이트로 세우지 않기로 했다. 급등 주 관찰 자체는 단계 6 기록과 그림 4에 남아 Q3의 답으로 쓴다.
