## 2. 실행 방법 (재현 가이드)

> 제3자가 그대로 따라 하면 같은 결과가 나오도록 작성합니다. _(단계 2~3 완료 후 채움)_

1. **실행 환경**: Python 3.10 이상, VS Code(노트북 실행용 Jupyter 확장 설치)
2. **라이브러리 설치** — `Project_01` 폴더에서 터미널을 열고:
   ```powershell
   python -m venv .venv              # 이 프로젝트 전용 파이썬 공간(가상환경) 만들기
   .venv\Scripts\activate            # 가상환경 켜기 (앞에 (.venv) 가 붙으면 성공)
   pip install -r requirements.txt   # 목록에 적힌 라이브러리를 정해진 버전으로 설치
   ```
3. **API 키 준비**: `.env.example`을 복사해 `.env`로 이름을 바꾸고, NAVER API HUB에서 받은 키를 입력
4. **데이터 수집** (API 호출은 이 한 번뿐):
   ```powershell
   cd Project_01                # 저장소 최상위에서 열었다면 먼저 이동
   .venv\Scripts\activate       # 가상환경 켜기
   python collect.py
   ```
   - 실행 전 확인: 줄 앞에 `(.venv)`, 경로 끝이 `\Project_01>` 인지. 터미널을 새로 열면 둘 다 초기화된다.
   → `data/search_trend_raw.json`(원본 응답), `data/search_trend_weekly.csv`(분석용 표) 생성
5. **분석 실행**: _(단계 5에서 작성)_

- **파일별 설계 이유**
  - `requirements.txt`: 버전을 고정해야 다른 사람이 설치해도 같은 결과가 나온다. pandas 3.x와 matplotlib 3.11은 Python 3.11 이상 전용이라, 과제 조건(3.10 이상)에 맞게 **3.10에서 설치되는 최신 버전**으로 골랐다.
  - `requests`, `python-dotenv`: A2-02 미션에서 쓴 방식과 같다(API 호출 + `.env`에서 키 불러오기).
  - `ipykernel`: VS Code가 노트북 안의 코드를 파이썬에 전달해 실행하게 해 주는 연결 부품이다. 없으면 노트북이 실행되지 않는다.
  - `.gitignore`의 `.env`: 저장소가 Public이라 키가 한 번 커밋되면 외부에 노출된다. `!.env.example`은 "견본 파일은 예외로 올린다"는 뜻이다.
  - `.gitkeep`: Git은 빈 폴더를 기록하지 않는다. `data/`·`images/` 폴더 구조를 저장소에 남기려고 넣은 빈 파일이다.

  - **수집(.py)과 분석(.ipynb) 분리**: 분석을 몇 번 다시 돌려도 API는 다시 호출하지 않는다. 같은 CSV로 분석하니 결과도 매번 같다(재현성).

- **핵심 코드 해설**

  ① 요청 내용 (`KEYWORD_GROUPS`, `body`)
  ```python
  {"groupName": "통영", "keywords": ["통영 여행", "통영여행"]},
  ```
  - `groupName`은 결과표의 열 이름이 되고, `keywords`에 적은 표현들의 검색량은 **합쳐져** 하나의 값이 된다.
  - `body`의 네 항목(시작일, 종료일, 단위, 그룹)이 "무엇을 달라"는 주문서다. 주문서를 파일 맨 위 설정에 모아 두어, 조건을 바꿀 때 코드 속을 뒤지지 않아도 된다.

  ② 인증 (`headers`)
  ```python
  "X-NCP-APIGW-API-KEY-ID": key_id,
  "X-NCP-APIGW-API-KEY": key,
  ```
  - 헤더는 요청에 붙이는 "봉투 겉면"이다. 네이버는 여기 적힌 키를 보고 누가 보낸 요청인지 확인한다.
  - 키는 코드에 직접 쓰지 않고 `load_keys()`가 `.env`에서 읽어 온다. 그래서 코드가 GitHub에 올라가도 키는 올라가지 않는다.

  ③ 실패 처리
  ```python
  if res.status_code != 200:
      sys.exit(f"[실패] HTTP {res.status_code}\n{res.text[:500]}")
  ```
  - `200`은 "정상 처리"라는 서버의 응답 번호다. 그 외 숫자면 원인을 보여 주고 **즉시 멈춘다**.
  - 멈추는 이유: 실패한 응답으로 계속 진행하면 빈 CSV가 저장되고, 분석 단계에서야 엉뚱한 오류로 드러나 원인을 찾기 어렵다.

  ④ 표로 변환 (`pivot`)
  ```python
  wide_df = long_df.pivot(index="period", columns="region", values="ratio")
  ```
  - 응답은 지역별로 따로 된 목록 3개다. 먼저 `(주, 지역, 값)` 한 줄씩 세로로 모은 뒤, `pivot`으로 "주를 행, 지역을 열"로 펼친다.
  - 날짜를 기준으로 줄을 맞추므로, 어떤 지역에 특정 주 값이 없으면 그 칸은 자동으로 빈칸(`NaN`)이 된다. 이것이 단계 4의 결측치 확인 대상이다.

  ⑤ 저장 인코딩
  ```python
  table.to_csv(CSV_PATH, encoding="utf-8-sig")
  ```
  - `utf-8-sig`는 파일 맨 앞에 "이 파일은 UTF-8"이라는 표시를 붙인다. 이 표시가 없으면 윈도우 엑셀이 한글 열 이름(통영·거제·남해)을 깨진 글자로 보여 준다.
